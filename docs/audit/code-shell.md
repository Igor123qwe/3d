## 1. Что есть: функции и потоки

### 1.1 Раскладка
- `.pl-root` — `position: fixed; inset: 0`, CSS‑grid `52px 1fr 24px` × `64px 1fr 340px`: шапка / (панель инструментов, холст, правая панель) / статусная строка (`planner.css:20-29`). В 3D левая колонка схлопывается в `0` (`css:824-826`).
- Мобильная раскладка `@media (max-width: 860px)`: одна колонка `hdr / canvas / tools / panel / status`, инструменты — горизонтальная лента, панель — снизу, `max-height: 44vh`, сворачивается кнопкой `▾/▴` (`css:969-1046`, `1350-1381`; `PlannerPage.tsx:3500-3502`). JS‑порог `isMobile = innerWidth < 860` (`PlannerPage.tsx:506`).

### 1.2 Шапка (`PlannerPage.tsx:3140-3336`)
Имя проекта (input, `history.silent`) + индикатор автосохранения (`saved/saving/error`, `3147-3150`) → переключатель режимов **Стройка / Мебель / Электрика** (`role=tablist`, скрыт в 3D, `3152-3161`) → переключатель **2D / 3D** (`3162-3169`) → отмена/повтор, зум −/%/+ (`3171-3188`) → **Проверка** со счётчиком проблем (`3190-3201`) → меню **Вид** (слои, фото‑вид, единицы, длина стены, шаг сетки, `3202-3246`) → меню **Проект** (Новый…, План картинкой…, Вставить из буфера, Открыть файл, Сохранить в файл, Экспорт PNG/SVG, Ссылка для телефона, `3247-3319`) → **?** справка (`3320-3330`). Меню закрываются только кликом по прозрачному `.pl-backdrop` (`3332`).

### 1.3 Панель инструментов (`3338-3434`)
Набор зависит от режима: в стройке 8 инструментов (`TOOLS`, `177-186`; у «Проём» нет горячей клавиши) + при подложке «По клику», «Уточнить», «Масштаб» (`3348-3369`); в мебели — Выбор, Рулетка, Каталог, ИИ, Зоны; в электрике — Выбор, Рулетка, «Проект». Внизу в стройке — «Замок» (все стены) и «Орто». Инструмент стройки сам включает режим стройки (`BUILD_TOOLS`, `189`, `508-514`); объект, выбранный из «Проверки»/3D, включает свой режим (`516-534`).

### 1.4 Правая панель (`3474-3513`)
Вкладки **Свойства / Каталог / Электрика / Проверка** (+ невидимая вкладка «Справка», открываемая только из шапки). Клик по «Каталог»/«Электрика» переключает режим (`3488-3489`).
- **Свойства** (`renderProps`, `1917-2616`): мебель (подпись, Ш/Г/поворот/высота, повороты, отразить, цвет, дублировать/удалить, карточка товара, блок электрики точки с группой и замечаниями, блок «3D‑модель» с GLB, зоны эргономики); стена (длина по оси/внутри/снаружи, толщина, длинная памятка, +Дверь/Окно/Проём, замок, удалить); проём (тип, ширина с datalist, положение ползунком, петли/сторона); комната (имя + чипы, пол, «На плане, м²» при подложке, площадь/периметр, размеры на план, «Обставить с ИИ…»); размерная линия. Без выделения — параметры новых стен, пошаговая карточка подложки (подготовить фото → получить стены → масштаб → подложка, `2419-2561`), сводка плана, список комнат с «✨», «Как работать».
- **Каталог** (`renderCatalog`, `2622-2779`): CTA «✨ Расставить с ИИ по пожеланиям», сегмент Схемы / Фото 3D / По ссылке, поиск, чипы категорий, сетка карточек с SVG‑глифами; Poly Haven с категориями и состояниями loading/error; товар по ссылке с ручной правкой габаритов.
- **Электрика** (`renderElectric`, `2781-3008`): 4 плитки статистики, `<details>` «Исходные данные и расстановка по нормам» (мощность, плита, потолок, 10 чекбоксов правил, «⚡ Спроектировать по нормам», «Убрать всю»), под‑вкладки Щит / Материалы / Нормы / Поставить.
- **Проверка** (`renderChecks`, `3010-3073`): сводка замечаний электрики, разрывы стен + «Замкнуть разрывы», чекбокс зон эргономики, список замечаний (клик центрирует объект), «Что проверяется».
- **Справка** (`renderHelp`, `3075-3136`): модели ИИ по задачам и расходы, правила дизайнеров, горячие клавиши.

### 1.5 Диалоги и оверлеи
- `StartDialog` «С чего начнём?» — загрузка (drop‑зона, файл, буфер), 3 шаблона с настоящими миниатюрами через `Scene`, «Пустой лист», «Продолжить». Показывается при первом входе и по «Новый…» (`273`, `3543-3553`).

- `FurnishDialog` — пожелания, чипы, область, чекбоксы, отчёт по комнатам.
- Оверлей перетаскивания (`3534-3542`), карточка «Чистый лист» на пустом холсте (`3515-3533`), тост (`3570`, 3,5 с, `398-402`), статусная строка: подсказка инструмента или прогресс ИИ + площадь/комнаты/сетка (`3564-3569`).
- Приём файлов `useFileIntake` — drop на окно, Ctrl+V, кнопка «Вставить из буфера», JSON текстом (`intake.ts`).

### 1.6 Хранение и состояние
Один слот `localStorage` `boop.planner.plan.v1` с дебаунсом 400 мс и откатом без `underlay.original` при переполнении (`351-374`); настройки UI `boop.planner.ui.v1` (слои, единицы, орто, толщина, **режим**, длина стены, `108-135`, `375-381`); `boop.planner.photo`, `boop.planner.wishes`. План из ссылки `#plan=` подтверждается `window.confirm` (`456-486`).

## 2. Что сделано хорошо

1. **Вход в продукт — как у лидеров.** Стартовый экран с настоящими миниатюрами шаблонов (`StartDialog.tsx:44-61`), один приёмник для drop/Ctrl+V/файла/JSON‑текста (`intake.ts:79-179`), оверлей «Отпустите, чтобы загрузить», карточка «Чистый лист» с тремя действиями, вопрос с вариантами вместо тихой замены проекта с обещанием Ctrl+Z (`PlannerPage.tsx:662-676`, `745-760`). Всё это покрыто тестами (`tests/askdialog.test.tsx`, `startdialog.test.tsx`, `intake.test.ts`).
2. **Режимы Стройка/Мебель/Электрика** держат согласованность: инструменты и панель зависят от режима, инструмент стройки сам включает стройку, выбор из «Проверки»/3D включает режим объекта (`508-547`), у каждого инструмента и режима — своя подсказка в статусной строке (`PlannerCanvas.tsx:325-380`).
3. **Дизайн‑система на уровне кода:** токены `--pl-*` (`css:2-19`), единые `pl-btn/pl-ibtn/pl-chip/pl-field/pl-stats/pl-issue/pl-hint-box`, один векторный набор иконок с `aria-hidden`/`focusable=false` (`icons.tsx:329-345`), у всех 37 кнопок в живой странице есть имя (aria-label/title/текст — проба a11y), `NumberField` применяет значение по Enter/blur, а не на каждый символ (`205-245`), `Menu.tsx` даёт `menuitemcheckbox`/`radiogroup`.
4. **Устойчивость мелочей:** автосохранение с деградацией и понятным тостом (`351-374`), пошаговая карточка подложки прячет тонкие настройки в `<details>` (`2545-2559`), состояния loading/error у Poly Haven и товара (`2733-2734`, `2664-2668`), Suspense‑заглушка 3D (`3437`). Пересчёты дешёвые: на плане из 90 объектов `buildRooms` 2,7 мс, `runChecks` 1,3 мс, `designElectrics` 0,7 мс; на плане ×3 — до 2,6 мс (`perf.ts`).

## 3. Трение и пробелы (с доказательствами)

Шкала: **blocker / major / minor / polish**.

### F1. Мобильная раскладка сломана: сетка шире экрана — **blocker**
На телефоне 390 px вся сетка становится 532 px: шапка не переносится (`.pl-header` flex без wrap, `css:76-86`), а колонка `1fr` (`css:972`) не может стать уже min‑content шапки. Измерено: `header.scrollWidth 532`, `panel.width 532`, правый край «?» = 526 при `innerWidth 390` (`findings.json: mobileRoot, mobileHeader`). Итог на скриншоте `shots/m01-main.png`: **меню «Проект», «Вид», «?», вкладка «Проверка» и кнопка сворачивания панели за экраном**, третья плитка статистики и правый край панели обрезаны; в туре клики по «Проект» и `.pl-tab-toggle` падали по таймауту (элемент вне вьюпорта). Причина появилась с переключателем режимов в шапке (`PlannerPage.tsx:3152-3161`, коммит `931b982`, 2026‑09‑25): на мобильной ширине он остаётся в шапке иконками (`css:1351-1357`). README:36 («Мобильная версия… панель‑шторка») и `docs/04-mobile.png` сняты до этого и уже не соответствуют. Для Telegram Mini App (README:6) это основной канал.

### F2. Шапка не помещается на ноутбуках 861–1140 px, имя проекта схлопывается — **major**
На 1024×640: `header.scrollWidth 1142 > 1024`, поле имени 18 px, «Проект» обрезан, «?» скрыт (`shots/l01-1024.png`, `findings.json: laptopHeader`). На 1280 имя — 39 px (`findings3.json: x.nameW`). Корень: `.pl-root input { min-width: 0 }` (`css:50-58`, специфичность 0‑1‑1) перебивает `.pl-name { min-width: 80px }` (`css:94-95`, 0‑1‑0) — вычисленный `min-width: 0px`; плюс `.pl-brand { flex: 1; min-width: 0 }` (`css:87-93`) отдаёт всё место переключателям.

### F3. Диалоги не модальны для клавиатуры и слоёв — **major**
- Стартовый экран не берёт фокус (`document.activeElement = BODY`), в `StartDialog.tsx` нет `focus()`; Tab уходит из диалога на элементы под ним (проба: фокус покинул `.pl-start`); `AskDialog` ставит фокус на главный вариант (`AskDialog.tsx:100-102`), но ловушки и возврата фокуса нет.
- Горячие клавиши работают под открытым диалогом: `w` при стартовом экране включил «Стена» (`toolAfterWUnderStart`); Ctrl+S скачал файл (`ctrlSUnderStartDialogDownloads: true`) — обработчики на `window` фильтруют только поля ввода (`PlannerPage.tsx:804-818`, `PlannerCanvas.tsx:988-991`).
- Тост под диалогом: `.pl-toast z-index: 20` (`css:817`) против `.pl-start-backdrop 40` / `.pl-ask-backdrop 50` (`css:1053`, `1387`) — «План сохранён в файл» показался за затемнением (`shots/d06-toast-under-dialog.png`); то же случится с «Отчёт скопирован» из открытого диалога «Распознано» (`1788-1793`).

### F4. Esc не закрывает «Расставить мебель с ИИ», пока фокус в поле пожеланий — **major**
Текстовое поле получает фокус при открытии (`FurnishDialog.tsx:52`) и на `keyDown` вызывает `e.stopPropagation()` (`143-146`); слушатель Esc висит на `window` (`51-58`) и событие до него не доходит. Проба: после Esc диалог открыт (`furnishOpenAfterEscInTextarea: true`), после клика по заголовку и Esc — закрыт. Во время работы ИИ отменить нельзя вовсе (`54`, `173-176`).

### F5. Долгие операции ИИ без отмены и с прогрессом в статусной строке 11,5 px — **major**
Распознавание — цепочка запросов (подписи по комнатам батчами `1109-1111`, размеры по одному `1071-1091`, перечитывание спорных `1193`, вторая попытка `1664`), прогресс — только текст `aiBusy` в футере (`3565`) и надпись на кнопке, которая показывает лишь первую стадию: сравнение со строкой `'Читаю план…'` (`2443`). `ai.ts` принимает `AbortSignal` (`ai.ts:113, 125, 231`), но `PlannerPage` его не передаёт (grep `AbortController` — 0). На мобильном статус 22 px с `text-overflow: ellipsis` (`css:789-806`) — подсказка ««Кровать 160×200»: кликните, куда поставить…» видна на 512 px при экране 390 (`findings3.json: mobilePlacing`).

### F6. Тупиковые CTA при выключенном ИИ и текст для разработчика — **major**
«✨ Расставить с ИИ по пожеланиям» (`2625`) и «✨ Обставить с ИИ…» (`2352`) показываются независимо от `ai.enabled` (в отличие от «✨» у комнат, `2585`); диалог затем пишет «нужен ключ ROUTERAI_API_KEY в .env» (`FurnishDialog.tsx:109`), карточка подложки — про «.env рядом с package.json» (`2480`), справка — «добавьте на сервере ключ» (`3105`). На публичном демо GitHub Pages (README:7) сервера нет вовсе — пользователь получает инструкцию по конфигурации.

### F7. В 3D каталог и электрика — тупик, зум в шапке не работает — **major**
Вкладка «Каталог» в 3D переключает режим и позволяет выбрать предмет (`3488`), но `PlannerCanvas` не смонтирован (`3436-3440`): ничего не происходит, тоста нет (`in3dAfterPick.toast: null`), а после возврата в 2D остаётся режим установки («кликните, куда поставить», `toolAfter3dPick`). Кнопки −/%/+ в шапке (`3177-3188`) в 3D — no‑op (`canvasRef.current` = null). Одновременно две подсказки: `.pl3d-hint` внизу сцены и статусная строка с другим текстом (`shots/d21-3d.png`).

### F8. Нативные `window.confirm/prompt` рядом с `AskDialog` — **major**
Пять мест: план из ссылки (`466`), калибровка через `prompt` с подстановкой «372» (`823`), обводка «Заменить нарисованные стены? «Отмена» — добавить» (`1555`), замена/удаление электрики (`1860`, `1871`). Это противоречит заявленному принципу `AskDialog.tsx:75-77` и README:72; в `confirm` «Отмена» означает действие («добавить»), а не отмену.

### F9. Термины расходятся между README, справкой и интерфейсом — **major**
- README:16 «**«Файл»** → «Загрузить схему картинкой…»» и справка «Через «Файл» можно сохранить JSON» (`3134`) — меню называется **«Проект» → «План картинкой…»** (`3250`, `3268`).
- README:28 и :261 «Вкладка **«⚡»**… нажмите **«Расставить»**» — вкладка «Электрика» (`3480`), кнопка «⚡ Спроектировать по нормам» (`2852`).
- README:257 «кнопка «Зоны» слева» — есть только в режиме «Мебель» (`3426-3433`).
- Слово **«Проект»** — это меню файлов (`3250`), инструмент электрики (`3398`) и заголовок «Проект электрики» (`2786`).
- Картинка плана называется «схема» (`752`, `2421`, `3213`), «план картинкой» (`3268`), «картинка плана» (`3519`), «подложка» (`3539`) в соседних экранах; «объектов» (`2574`) против «предметов» (`750`).

### F10. Единицы «см/мм/м» действуют только на подписи холста — **minor**
Все поля панели подписаны «, см» и считают в сантиметрах (`1933-1948`, `2141`, `2147`, `2157`, `2230`, `2369`, `2829`), периметр и ширина картинки жёстко в «м» (`2334`, `2500`), хотя `unit` переключается в меню «Вид» (`3226-3235`) и обещан в README:14.

### F11. Вкладки панели без семантики, «Справка» вне вкладок — **minor**
`.pl-tab` не имеют `role`/`aria-selected` (`3484-3499`; проба `panelTabsRoles`), тогда как переключатели шапки — `tablist/tab` (`3153-3168`). При открытой справке ни одна вкладка не активна (`activeTabWhenHelp: null`, `3320-3330` vs `3476-3482`); закрыть её можно только выбрав другую вкладку.

### F12. Меню без клавиатуры — **minor**
`Dropdown` (`Menu.tsx:16-20`) объявляет `role="menu"`, но фокус остаётся на кнопке (`menuFocusAfterOpen: pl-btn active`), Esc не закрывает (`menuClosesOnEscape: false`), стрелок нет; единственный способ закрыть — клик по `.pl-backdrop` (`3332`), недоступный с клавиатуры.

### F13. Мобильные мелочи: свёрнутая панель наезжает на статус, цели касания < 44 px — **minor**
`.pl-panel.closed { max-height: 40px }` (`css:1022-1024`) при высоте вкладок 54 px и `overflow: visible` — низ вкладок 837 px при статусе от 822 (`findings3.json: mobilePanelClosed`). `aria-label="Свернуть панель"` не меняется при развёрнутом/свёрнутом состоянии (`3500`). Кнопки шапки на мобильном 34×26 и 30×30 px (`css:145-150`, `999-1002`; `mobileHeader.boxes`). Лента инструментов прокручивается (600 > 532) без индикатора (`mobileLayout.toolsScroll`).

### F14. Юникод‑глифы и эмодзи в кнопках вопреки собственному правилу `icons.tsx` — **minor**
`icons.tsx:3-6` объясняет отказ от символов юникода (на Windows заменяются квадратами), но панели по‑прежнему на них: `⟲ ⟳ ↻ ⇋` (`1951-1954`), `⧉` (`1976`), `🗑` (`1985`, `2206`, `2268`, `2391`), `↔` (`2350`), `✨` (`2353`, `2593`, `2626`, `3565`), `⚡` (`2852`, `3020`), `⬇` (`2957`), `⛔ ⚠️ ℹ️ ✅` (`2979`, `3052`, `3056`), `▾ ▴` (`3501`), `FurnishDialog.tsx:86, 177`, `View3D.tsx:496-507` (📷 📱), эмодзи категорий каталога (`catalog.ts:17-27`).

### F15. Панели свойств перегружены и не различают типы объектов — **minor**
- Блок «3D‑модель» с полем GLB показывается любому предмету (`2062-2101`), включая розетки/выключатели (`symbol: true, resizable: false`, `catalog.ts:434-437`), где он бессмыслен.
- У стены — памятка на 347 символов при каждом выделении (`2166`), дублирующая подсказку статусной строки на 221 символ (`PlannerCanvas.tsx:328-333`); `shots/d25-props-wall.png`.
- Статистика электрики — 4 плитки по 73 px без переноса (`css:607-626`, `2787-2806`): «кВт расчёт / выделено» в четыре строки (`shots/d12-electric-initial.png`).
- Чипы категорий занимают 154 px высоты панели до первой карточки (`2748-2757`; `catalogChipRows: 154`, `shots/d07-catalog.png`).

### F16. Дубли путей к одному действию — **minor**
«Зоны эргономики» переключаются в трёх местах (`3049`, `3427`, `3219`); «Проверка» — кнопка шапки (`3190-3201`) и вкладка (`3481`) с одинаковым бейджем; точки электрики ставятся из Каталога→«Электрика» (`2752-2756`, `catalog.ts:25`) и из Электрика→«Поставить» (`2989-3005`); «Ссылка для телефона» — в меню «Проект» и на панели 3D (`3308-3316`, `View3D.tsx:506`).

### F18. Отладочная информация в пользовательских экранах — **polish**

### F19. Побочные эффекты навигации — **minor**
Клик по вкладке «Каталог» меняет режим и снимает чужое выделение (`3488-3489`, `537-547`; проба `modeAfterCatalogTab: Мебель`). На мобильном выбор комнаты из списка закрывает панель (`1908`), и свойства, ради которых кликали, скрываются (`mobilePanelAfterFocus: closed`). Режим сохраняется между сессиями (`127`) — приложение может открыться в «Электрике» с тремя инструментами.

### F20. Порог мобильности расходится — **polish**
JS `innerWidth < 860` (`506`) против CSS `max-width: 860px` (`969`): на ровно 860 px CSS мобильный, JS — нет.

### F21. Доступность: запрет масштабирования, мелкий кегль, контраст — **minor**
`index.html:10` — `maximum-scale=1, user-scalable=no` (WCAG 1.4.4). Подписи инструментов 9,5 px (`css:450-454`), размеры в каталоге 10,5 px (`683-686`), заголовки меню и подписи плиток 11 px (`323-330`, `623-626`). ### F23. Горячие клавиши: пробелы в справке и наборе — **polish**
У «Проём» нет клавиши (`183`), у остальных инструментов есть. Таблица в справке (`3121-3133`) не упоминает Ctrl+S/Ctrl+O/Ctrl+V, Alt+тянуть, Alt+щелчок, ввод длины цифрами, Shift+стрелки — всё это описано в README:79-95 и в подсказках.

### F25. Внешние шрифты — **polish**

### F26. Тесты и хуки для автоматизации — **minor**

## 4. Риски

**Производительность.** Сейчас дёшево: пересчёт комнат/проверок/электрики на плане из 90 объектов — 2–3 мс, на плане ×3 — ≤ 2,6 мс (`perf.ts`), хотя `check` и `design` пересчитываются на любое изменение `plan` — и при вводе имени, и на каждом тике ползунка прозрачности (`345`, `1846`, `2517` через `history.silent`). Реальная стоимость — подложка: `JSON.stringify` плана с base64‑картинкой (и `original`) при каждом автосохранении (`356-360`), лимит `localStorage` ~5 МБ обрабатывается только тостом (`369`); карты расстояний растра — три `Float32Array` на пиксель подложки, живущие в `useRef` всю сессию (`1239-1245`, `838-846`): для фото 4000×3000 это ~48 МБ × 3.

**Надёжность/сопровождаемость.** `PlannerPage.tsx` — god‑компонент: 3583 строки, 48 `useState`, 15 `useRef`, 15 `useEffect`, 90 внутренних констант/функций, 788 строк пайплайна распознавания внутри компонента страницы (`1029-1817`), пять `render*`‑замыканий пересоздаются каждый рендер, 8 `eslint-disable react-hooks/exhaustive-deps` (например, `onSelect` с `[]`, `534`; `keydown` перерегистрируется на каждое изменение плана, `804-818`). Пять независимых слушателей `keydown` на `window` (StartDialog, AskDialog, FurnishDialog, страница, холст) без единого понятия «открыт модал» — источник F3/F4. Слои `z-index` назначены вручную (3, 5, 8, 9, 20, 40, 50, 60, 3000) — уже дают F3.

**Хранение.** Один слот плана; план из ссылки заменяет сохранённый по `confirm` (`466`); «Продолжить» знает только последний проект; переполнение хранилища = потеря автосохранения с одним тостом.

**Внешние зависимости в рантайме.** Google Fonts, polyhaven.com, страницы магазинов, серверный ИИ; ошибки показаны текстом без повтора (`2733-2734`, `1813`); список категорий Poly Haven кэшируется в состоянии навсегда (`493`).

**Продуктовый.** F1 бьёт по основному каналу — Telegram Mini App на телефоне; README и `docs/04-mobile.png` обещают рабочую мобильную версию.

## 5. Сравнение с лидерами (ориентир) и идеи

README (:68) прямо называет образцы — Floorplanner, RoomSketcher, HomeByMe; `docs/plan-from-image.md` добавляет Planner 5D, Coohom, Sweet Home 3D. По оболочке у них общий знаменатель, которого здесь нет: галерея проектов (несколько планов, переименование, дубликат), сворачиваемая/растягиваемая боковая панель, контекстная мини‑панель у выделенного объекта (поворот/удалить/дублировать без похода в правую панель), шпаргалка клавиш по `?`, подсказки‑онбординг для первых шагов, тёмная тема, мобильная «шторка» с ручкой перетаскивания и адаптивная шапка. Что здесь уже на уровне лидеров: стартовый экран, единый приём файлов, режимы, подсказки инструментов, проверка с переходом к объекту.

Идеи (кратко, без реализации):
1. **Сетка и шапка.** `grid-template-columns: minmax(0, 1fr)`; шапка с переносом или второй строкой на ≤ 860 px; переключатель режимов на мобильном — в ленту инструментов или сегмент над холстом; имя проекта — в заголовок меню «Проект»; починить `.pl-name` (специфичность `min-width`). Проверять overflow шапки автотестом на 390/1024/1440.
2. **Один примитив Modal** (начальный фокус, ловушка, возврат фокуса, Esc, `inert` для фона, флаг «модал открыт», который выключает горячие клавиши и Ctrl+S/V) — для Start/Ask/Furnish; тост над диалогами. Заменить 5 `confirm/prompt` на `AskDialog`/встроенное поле (калибровка — как поле у размера комнаты `.pl-side-edit`).
3. **Меню и вкладки по ARIA:** roving tabindex и стрелки в `Dropdown`, Esc, `aria-controls`; `tablist` у панели; «Справка» — вкладка или поповер у «?».
4. **Прогресс и отмена ИИ:** карточка задачи со стадиями и кнопкой «Отменить» (`AbortSignal` уже есть в `ai.ts`), подпись кнопки — по текущей стадии, `aria-live` для прогресса и тостов, очередь тостов с длительностью по длине и закрытием; ошибки — липкие.
5. **ИИ выключен:** прятать/дизейблить CTA с человеческим объяснением («в этой версии ИИ не подключён»), без `.env`; на статическом хостинге — отдельный текст.
6. **3D:** прятать/блокировать «Каталог» и «Электрика» с подсказкой «вернитесь в 2D» или переносить выбранный предмет в 2D автоматически; зум в шапке — либо к камере 3D, либо скрыть; одна подсказка вместо двух.
7. **Словарь терминов** (Проект = файл, План = чертёж, Схема = картинка‑подложка), правка README:16/28/257/261 и `3134`; инструмент электрики «Проект» → «Щит»; один вход в «Проверку».
8. **Панели — прогрессивное раскрытие:** памятка стены → одна строка + «Подробнее»; блок «3D‑модель» только для несимвольных предметов; статистика электрики 2×2 или лента; чипы категорий — горизонтальная прокрутка или `select`; поля с суффиксом текущих единиц и пересчётом мм/м.
9. **Иконки:** заменить оставшиеся глифы на `Icon` (rotate, flip, duplicate, trash, download, chevron, alert), категории — линейными иконками.
10. **Паритет с лидерами:** список проектов (IndexedDB, несколько слотов), сворачиваемая правая панель на десктопе и bottom‑sheet с ручкой на мобильном, контекстная мини‑панель у выделения (снимает часть нагрузки с панели свойств на телефоне), шпаргалка `?`, тёмная тема через токены и `Telegram.colorScheme`, поиск по каталогу и действиям (палитра команд).
11. **CSS:** дотокенизировать цвета, определить `--pl-border`, слить медиа‑блоки, убрать `!important`, контейнерные запросы для панели; `.pl-badge` и неактивные переключатели — до 4,5:1; кегль подписей ≥ 11 px.
12. **Тесты оболочки:** RTL‑тесты `PlannerPage` (меню, вкладки, режимы, модальность, Esc), Playwright‑смоук на трёх ширинах с проверкой `header.scrollWidth <= clientWidth`; `data-*` атрибуты в `Scene` для e2e.
