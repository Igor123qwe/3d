# Набор для проверки распознавания

Это **набор для проверки**, а не для обучения: несколько настоящих планов с
эталоном, проверенным вручную, и метрики, которые считаются одинаково от
прогона к прогону. По нему видно, стало ли хуже после правки кода, и на чём
именно.

## Как прогнать

```bash
npm run bench              # все планы, подписи берутся из эталона
npm run bench -- --json    # то же в JSON, чтобы сравнивать прогоны
npm run bench -- bti-dvushka   # только один план
```

Прогон поднимает dev-сервер, грузит каждое фото в приложение и прогоняет тот
же код, что и кнопка «Распознать с ИИ». Подписи (имена, площади, размеры,
двери и окна) берутся из эталона: так проверяется геометрия — сегментация,
решатель, формы, — а не то, как модель прочитала цифры в этот раз. Чтобы
проверить и чтение цифр, нужен ключ и отдельный прогон через интерфейс.

## Что измеряется

| Метрика | Что значит |
|---|---|
| пропуски | помещения из эталона, которых нет на чертеже. Главная метрика: пока она не ноль, остальное неважно |
| лишние | комнаты на чертеже, которых нет в эталоне |
| площади | максимальное расхождение с подписанной площадью, м² |
| размеры | максимальное расхождение подтверждённого размера, см |
| форма | худший IoU контура комнаты с областью на картинке; ниже — потерян выступ |
| стены | доля длины стен, лежащей на линиях фото |
| проёмы | сколько встало из названных |
| правок | грубая оценка ручной доработки: пропуски + лишние + комнаты с плохой формой + размеры вне допуска + непоставленные проёмы |

## Как добавить план

1. `bench/plans/<имя>/plan.webp` (или .png/.jpg) — само фото.
2. `bench/plans/<имя>/reference.json`:
   - `labels` — что читается на плане глазами: комнаты с площадями и
     размерами, двери и окна, размерные цепочки. Формат — тот же, что модель
     возвращает в `api/plan` (см. `src/planner/aicontract.ts`).
   - `expect` — чего мы ждём от чертежа: число областей, границы масштаба,
     доля стен на линиях, число проёмов, допуски по площадям и размерам,
     форма комнаты (`shape`: `rect` — прямоугольная, `notched` — с вырезом).
     Если комната на снимке чем-то закрыта, пометьте её `covered`: её размеры по
     картинке не проверяются, зато отчёт обязан назвать её подпись спорной.
   - `expect.openingList` — двери и окна поимённо: дверь — между какими
     комнатами (`{"kind":"door","rooms":["1","4ж"]}`), окно — в какой. Подписи
     эталона проёмов не содержат: так меряется поиск проёмов по картинке, а
     не то, что подсказал эталон. Пропущенный и лишний проём — по правке.
   - `texts` — размеры, подписанные на плане, по месту: точка подписи в долях
     картинки и что в ней написано (`{"x":0.5,"y":0.1,"text":"3,72"}`). С ними
     лист вырезок «читается» по эталону: в каждой найденной рамке — то число,
     чья точка в неё попала. Так проверяются поиск подписей, привязка числа к
     стене и подгонка, а не то, как модель прочитала цифры.
   - `expect.rooms[].edges` — длины граней, подписанных на плане (ниша 129 и
     68, уступ 26): у комнаты должна быть грань такой длины с допуском
     `edgeTolCm` (3 см). Ширина и глубина ниши не видят: ниша 103 × 38 вместо
     1,29 × 0,68 рамку прихожей не меняет.
   - `note` — что на этом плане сложного: обрезанный край, тени, ниша.
3. Прогнать `npm run bench` и убедиться, что метрики осмысленные: эталон
   описывает план, а не подгоняется под нынешний результат.
